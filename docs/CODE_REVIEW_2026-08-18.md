# pic2d 代码审查(2026-08-18,V4R3 运行等待期间)

逐文件重读 `include/pic2d/` 全部头文件与 runner,记录发现、已修项与
遗留项。配套新增主机端单元测试 `tests/test_units2d.cu`(5 项,全部通过,
不占用 GPU)。

## 一、本次发现并已修复

1. **kappa 抽样与位置抽样的随机数流冲突(真实 bug)**。加载器的 χ²
   抽样此前使用 Gaussian 流 8–14(均匀分布槽位 16–29),与位置拒绝
   采样的槽位区间(16–207)重叠:同一 marker 的坐标与速度大小由相同
   的随机数决定,初始条件带有系统性的位置-速度关联。已把 χ² 抽样移到
   流 105 起(槽位 ≥210)。**影响范围:V3 Li 基准运行带此缺陷加载**;
   其结论(gap 功率下降三个数量级等)为积分量、经相位混合后稳健,
   但 GPU 空闲后应以修正版重跑 V3 复核(遗留项 D1)。
2. **kappa 分布 × 弯曲背景无保护**:bi-kappa 的 (E,μ) 映射未实现,
   原代码会把 bi-Maxwellian 的映射公式错误地套用于 kappa 而不报错。
   已加入 deck 硬性检验:dist=1 只允许 uniform/tilted 背景。
3. **deck 解析对未知键静默容忍**:拼写错误的键会被忽略并以默认值运行。
   已加入逐节已知键清单与警告输出。
4. **长时间运行缺少健康自检**:已在 Sim2D 加 `healthy()`(全 marker
   有限性扫描 + 场能量有限性),runner 每一万步检查,失败时**先写
   紧急 checkpoint(ckpt_emergency.bin)再退出**——病理不再毁掉整夜
   运行且留下可诊断状态。
5. 单元测试步长错误(测试自身):float 精度函数的数值微分步长 1e-4
   低于 ulp 噪声,改为 0.01。

## 二、审查确认无问题的要点(记录以免重查)

- 位置每步回绕进盒内,cell 键值截断到边界格,CSR 按 marker 序号索引
  (排序间隔内稳定),tiled 路径每个 marker 恰好处理一次;
- 反射墙翻转 u∥ 后不重算当步位移:单步穿透深度小,电荷沉积与轨迹
  一致,物理可接受(已在代码注释说明);
- filter_j 采用拷回而非指针交换:Sim2D::step 开头捕获的视图在整步内
  保持有效(交换会造成悬空指针,审查时验证过此风险);
- 冷流体在吸收框内同样被阻尼(防边缘共振累积);
- checkpoint 不保存 CSR:恢复后 `sorted_once=false` 强制首步重排序。

## 三、遗留项(按优先级)

- **D1(GPU 空闲后)**:修正版随机数重跑 V3 Li 基准,确认判据不变;
- **D2(性能)**:场求解部分 ppc=1 下限 88 ms/step,其中约 50 ms 无法
  用访存量解释(理论下限约 35 ms)——需 Nsight profiling 定位;
  候选:kernel 尾部等待、idx() 回绕算术、启动间隙;
- **D3**:加载器的导向中心偏移用 γ=1(相对论种群的 shell 边缘放置
  有轻微偏差,量级为回旋半径的 γ 修正)——待 kappa 映射一并整理;
- **D4**:runner 中 probe/sline/fv 的输出间隔为硬编码,应移入 deck;
- **D5**:kinetic2d.hpp 已超过 500 行,加载器可拆分为 loader2d.hpp;
- **D6**:Fields2D::step()(P1 时期的纯场推进)现仅供波动测试使用,
  与 Sim2D::step 并存,需在注释中明示以免误用(已部分说明);
- **D7**:多 GPU 的 z 方向分域——Range 接口契约保持,未实现。

## 四、结构评估

分层清晰:background2d(解析背景场族)→ fields2d(Yee + 冷流体)→
particles2d/sort2d(存储与排序)→ kinetic2d(单粒子物理,flat 与
tiled 内核共用同一 device 函数)→ diag2d(诊断)→ sim2d(编排)→
checkpoint2d → warden2d(deck 驱动 runner)。单粒子物理只有一份实现
是本次重构后最重要的结构保证;deck 检验在分配内存前拒绝不合格配置
的机制已多次证明价值(两次拒绝都对应真实的物理问题)。
